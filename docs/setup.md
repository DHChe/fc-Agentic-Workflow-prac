## 0. 준비물

계정 4개. 전부 무료 플랜으로 된다.

| 서비스 | 쓰는 곳 | 비고 |
|---|---|---|
| **Vercel** | 배포 + Blob 파일 저장 | Hobby |
| **Neon** | Postgres 2개(운영용·테스트용) | Vercel 마켓플레이스로 만들면 환경변수가 자동 주입된다 |
| **Clerk** | 로그인 | ADR-29에 따라 **개발 인스턴스 하나**를 로컬·테스트·운영에 함께 쓴다 |
| **Anthropic** | Claude API | 결제 수단 등록 필요 |

Node는 22. `.nvmrc`와 Vercel 프로젝트 설정이 같아야 한다.

> **비용 주의**: Anthropic만 종량제다. 하루 사용 한도 50은 코드 상수로 박혀 있어(11절) 폭주하지는 않지만, 요금은 실제로 나간다.

## 1. 외부 서비스 만들기

**리전을 전부 싱가포르 `sin1`로 맞춘다.** 화면이 한국어이고 날짜 기준이 Asia/Seoul이라 사용자가 한국에 있기 때문이다. 이유와 대안 비교는 ADR-28.

> ⚠️ **Blob과 Neon의 리전은 만든 뒤에 바꿀 수 없다.** 처음에 틀리면 지우고 다시 만들어야 한다.

1. Vercel 프로젝트를 만들고 GitHub 저장소를 연결한다
2. Vercel 마켓플레이스에서 **Blob 스토어 1개**를 만든다
3. Vercel 마켓플레이스에서 **Neon 프로젝트 2개**를 만든다 — 운영용, 테스트용
   - 테스트용을 따로 두는 이유: 로컬 개발과 프리뷰 배포가 운영 데이터를 건드리지 않게 하려고
4. Clerk 앱을 만든다 (개발 인스턴스)
5. Vercel 프로젝트 설정에서 **함수 리전을 `sin1`** 로 바꾼다 (기본값은 미국이다)

> 💡 `vercel integration add`, `vercel blob create-store`, `vercel env pull`은 `.env.local`을 다시 쓰면서 **주석을 지운다**(값은 유지). 통합을 추가할 때는 `--no-env-pull`을 붙인다.

## 2. Clerk 설정

대시보드에서 셋을 맞춘다. 근거는 11절·ADR-1·ADR-19·ADR-29.

- **가입 모드 = Restricted** (초대받은 이메일만 가입)
- **로그인 수단 = 이메일 + 비밀번호만.** 소셜 커넥션은 끈다
- **사용자 계정 삭제 끄기** — `User & authentication` → `User model`
  방문자가 시연 계정을 지워 버리는 것을 막는다

> ⚠️ **Clerk 운영 인스턴스는 만들지 않는다.** 소유한 도메인과 DNS 레코드가 필수라 `*.vercel.app`으로는 만들 수 없다. 대가(로그인 화면의 개발 배지, 가입 100명 한도)는 감수하기로 했다 — ADR-29, PRD 10.3.

## 3. 시연 계정 만들기

1. Clerk 대시보드에서 사용자를 **직접 만든다.** 초대 절차는 필요 없다
2. **비밀번호는 무작위로 넣고 기록하지 않는다.** 아무도 몰라야 한다
   심사자는 비밀번호가 아니라 서버가 발급하는 일회용 로그인 표로 들어온다(ADR-19). 공개된 비밀번호는 방문자 한 명이 바꾸면 전부 잠긴다
3. 그 사용자의 `userId`를 복사해 둔다 → 다음 단계의 `DEMO_USER_ID`

## 4. 환경변수 채우기

**이름·용도는 `ARCHITECTURE.md` 10절 표가 기준이다.** `.env.example`에도 같은 이름이 빈 값으로 들어 있다.

```bash
cp .env.example .env.local
```

넣는 곳이 둘이다.

| | 로컬 `.env.local` | Vercel 프로젝트 |
|---|---|---|
| DB 주소 | **테스트용** Neon | **운영용** Neon |
| 테스트 모드 | 필요하면 켠다 | **넣지 않는다** |
| 나머지 | 같은 값 | 같은 값 |

규칙 둘:

- **비밀값에 `NEXT_PUBLIC_` 접두사를 붙이지 않는다.** 그 접두사가 붙으면 브라우저로 내려간다
- **`SLIPSCAN_TEST_MODE`를 프로덕션·프리뷰에 넣지 않는다.** 가짜 응답이 실제 사용자에게 간다(PRD 10.2)

> 💡 `vercel env pull`은 민감(sensitive) 변수의 값을 되돌려주지 않고 **`[SENSITIVE]`라는 문자열**을 쓴다. 받아쓴 파일을 보고 "값이 잘못됐다"고 판단하면 안 된다. 2026-09-19에 이 착각으로 잘못된 id로 시드를 한 번 돌렸다.

## 5. DB 준비 — ⚠️ 빠뜨리기 쉬운 단계

> **배포해도 테이블은 생기지 않는다.** 빌드 명령이 `next build` 하나뿐이라 마이그레이션이 돌지 않는다. **DB마다 손으로 한 번씩** 돌려야 한다.
>
> 2026-09-19 공개 직전에 운영 DB에 테이블이 **하나도 없다는 것**을 발견했다. 모르고 공개했으면 첫 방문자가 로그인하자마자 에러를 봤을 것이다.

**테스트용 DB** (로컬 개발):

```bash
npm run db:migrate
```

**운영용 DB**: `.env.local`이 테스트용을 가리키므로, 운영 주소를 앞에 붙여 준다. `drizzle.config.ts`와 시드 스크립트의 `process.loadEnvFile`은 셸에 이미 있는 값을 덮지 않기 때문에 이렇게 하면 그 값이 쓰인다.

```bash
DATABASE_URL="<운영 Neon 주소>" npm run db:migrate
```

## 6. 시연 데이터 넣기

```bash
npm run seed:demo            # 테스트용 DB
npm run seed:demo -- --verify   # 확인
```

운영용 DB에는 4번과 같은 방식으로 주소를 앞에 붙인다. `DEMO_USER_ID`와 `BLOB_READ_WRITE_TOKEN`도 함께 준다.

시드가 넣는 것: 문서 10건 · 거래 14행 · 지난달 보고서 1건. 날짜는 고정이고 **멱등**이라 다시 돌리면 기존 시연 데이터를 지우고 새로 넣는다. 자세한 규칙은 11절.

> ⚠️ `DEMO_USER_ID`가 비어 있으면 시드는 **즉시 중단한다.** 엉뚱한 계정에 데이터를 넣지 않기 위한 장치다.

## 7. 배포

1. Vercel 프로젝트 설정 확인 — Framework Preset `Next.js`, Node `22.x`, 함수 리전 `sin1`
2. `develop`에서 작업하고, 배포할 때가 되면 **`develop` → `main` 릴리스 PR**을 연다
3. `main`에 병합되면 자동 배포된다. **`main`에 직접 push하지 않는다**
4. **배포 보호(Deployment Protection)를 끈다.** 켜져 있으면 외부인이 Vercel 로그인 화면에 막힌다

> ⚠️ **`main`에 앱 코드가 없는 상태로 배포 보호를 먼저 끄면 빈 사이트가 공개된다.** 릴리스를 먼저 하고 보호 해제를 나중에 한다.

배포된 주소는 Vercel이 정한다. 원하는 이름이 이미 남에게 쓰이고 있으면 접미사가 붙는다. **실제 주소는 Vercel 프로젝트의 Domains에서 확인한다** — 짐작하지 않는다.
