## 1. 한 줄 정의

경리·회계 담당자가 영수증 사진이나 카드 명세서 PDF를 올리면, Claude가 거래 내역을 읽어 표로 정리하고, 월별 지출 통계와 보고서를 만들어 주는 웹 앱.

## 2. 목적과 배경

- **목적**: 데모·포트폴리오용 MVP. Vercel 무료 플랜에 배포해 누구나 접속해서 시연을 볼 수 있어야 한다.
- **배경**: 중소기업에서 직원 영수증을 모아 정리하는 일은 담당자 한 명이 손으로 한다. 사진을 올리기만 하면 금액·가맹점·카테고리가 자동으로 정리되고, 월말에 보고서까지 나오는 흐름을 보여주는 것이 이 MVP의 핵심이다.
- **성공 기준(시연 시나리오)**: 심사자가 랜딩의 "시연 계정으로 들어가기" 버튼으로 들어옴 → 미리 채워진 대시보드를 봄(통계는 거래가 있는 가장 최근 달) → 영수증 1장을 올림("샘플로 해보기" 버튼으로 가능) → 1분 안에 추출 결과 확인 → 그 달 통계에 방금 올린 건이 더해진 것을 확인 → 보고서 버튼을 눌러 글이 실시간으로 써지는 것을 봄. 이 다섯 단계가 끊김 없이 되면 성공. 초 단위 여정은 USER_FLOWS.md J1.
- **범위 판단 기준**: 이 다섯 단계(J1)에 쓰이지 않는 기능은 10.1로 보낸다.

## 3. 사용자

| 역할 | 누구 | 하는 일 |
|---|---|---|
| 담당자(주 사용자) | 경리·회계 담당자 1명 | 직원에게 받은 영수증 사진, 본인이 찍은 영수증, 카드 명세서 PDF를 올리고 결과·통계·보고서를 본다 |
| 관리자 | 프로젝트 소유자(본인) | 앱 안의 권한이 아니다. Clerk 대시보드(초대 보내기, 시연 계정 만들기)와 시드 스크립트를 다루는 사람이다. 앱 안에서는 담당자와 똑같다 |
| 심사자 | 포트폴리오를 보는 사람 | 랜딩의 "시연 계정으로 들어가기" 버튼으로 들어와 둘러본다. 아이디·비밀번호는 공개하지 않는다 |

- 계정은 **개인 단위**다. 회사·팀·소속 개념은 없다. 로그인한 사람이 올린 문서만 그 사람에게 보인다.

## 4. MVP 범위 (포함 기능)

### F1. 랜딩 페이지
- 한 화면짜리 소개: 제목 한 줄, 특징 3개, 버튼 두 개.
  - **"시연 계정으로 들어가기"**: 심사자용. 누르면 바로 시연 계정의 대시보드로 들어간다(F11).
  - **"로그인"**: 초대받아 가입한 사용자용. 로그인 화면으로 간다(F2).
- 이미 로그인한 사용자가 랜딩에 오면 대시보드로 자동 이동.
- 고지 두 줄을 랜딩에 둔다: (1) 올린 파일은 분석을 위해 Anthropic API로 전송된다. (2) 시연 계정은 공개 계정이라 올린 파일이 다른 방문자에게도 보인다. 문구는 USER_FLOWS.md 7.9.

### F2. 로그인과 가입 (초대 전용)
- 로그인 방식: **이메일 + 비밀번호**.
- 가입은 **초대받은 이메일만** 가능하다. 초대는 관리자가 Clerk 대시보드에서 보낸다(앱 안에 초대 화면은 없다).
- 가입 화면은 Clerk이 제공하는 화면을 쓴다. 초대 메일의 링크를 누르면 그 화면으로 간다. 앱 안에는 로그인 화면만 있다.
- 초대 링크를 클릭하는 것이 이메일 인증 역할을 하므로, 별도 인증 메일 단계는 없다.
- 구현은 Clerk의 초대 전용(Restricted) 모드를 쓴다. 자세한 흐름은 ARCHITECTURE 5.7.

### F3. 파일 업로드
- 한 번에 **파일 1개**. 앞 문서가 처리 중이어도 다음 파일을 계속 올릴 수 있다.
- 업로드 시 입력: 파일(클릭 선택)뿐이다. 문서 종류는 고르지 않는다(Claude가 판별). 업로드 중 진행률을 보여준다.
- **"샘플로 해보기" 버튼**: 올릴 영수증이 없는 심사자를 위해 `public/samples/`의 가짜 영수증 1장을 같은 경로로 올린다. 클릭 1회 = 사용 1회.
- 사용 횟수는 "올리기"를 누르는 시점(업로드 허가를 받을 때)에 1회 차감된다. 자세한 규칙은 F9.
- 형식·크기 제한은 7절 표 참조. 제한을 넘으면 업로드 전에 화면에서 막고 이유를 보여준다.
- PDF 페이지 수는 업로드 전에 알 수 없다. 20페이지를 넘는 PDF는 업로드된 뒤 "실패(페이지 초과)"로 표시되고, 이 건도 하루 사용 횟수에 들어간다.
- 큰 사진과 눕혀 찍힌 사진은 서버가 분석용 사본만 바로 세우고 줄여서 읽는다. 저장 원본은 그대로이고, 사용자는 이 과정을 의식하지 않는다.

### F4. 문서 분석 (Claude 추출)
- 업로드 직후 목록에 "처리 중"으로 나타나고, 뒤에서 Claude가 읽는다. 사용자는 기다리지 않아도 된다.
- 문서 1개에서 거래 0건 이상을 뽑는다. 영수증은 보통 1건, 카드 명세서는 여러 건. 영수증 여러 장이 한 파일(사진·PDF)에 있으면 각각 거래로 뽑는다.
- 문서 종류는 Claude가 `영수증 / 카드명세서 / 기타` 중 하나로 판별한다. 영수증도 명세서도 아니면 `기타`, 거래 0건, 상태 "완료"로 두고 "추출할 거래가 없습니다. 영수증과 카드 명세서만 읽습니다."를 보여준다. 영수증·명세서로 판별됐지만 거래를 못 읽은 경우도 같은 문구다.
- 거래 항목(8절)은 고정 형식(JSON 스키마)으로 받는다. 못 읽은 항목은 빈칸.
- 카테고리는 8개 고정 목록(8.3)에서만 고른다. 모르면 "기타".
- 예외 규칙
  - 합계금액을 못 읽은 거래: 빈칸으로 저장, 통계에서 제외, 상세 화면에 "금액 미인식" 표시.
  - 합계금액 0원은 정상 거래다. 못 읽은 것(빈칸)과 다르며 통계에 포함된다.
  - 거래일을 못 읽은 거래(미래 날짜로 읽힌 것 포함. 프롬프트가 null로 돌려준다): 업로드한 날짜로 대체하고 "날짜 추정" 표시.
  - 취소·환불 거래: 합계금액을 음수로 저장한다. 배지 없이 금액 칸에 음수로 보이고, 통계에는 음수로 합산한다(순지출).
  - 중복 거래(F7 참조): 나중에 들어온 쪽에 "중복(집계 제외)" 표시.

### F5. 문서 목록·상세·삭제
- 목록: 최근 순. 각 행에 문서 종류, 상태(처리 중 / 완료 / 실패), 거래 건수, 합계, 업로드 시각. 처리 중인 행의 종류·건수·합계 칸은 "—".
- **문서 합계** = 그 문서에서 추출된 금액의 합. 금액 미인식은 빼고 **중복 표시 거래는 포함**한다. 통계와 기준이 다르다. "이 영수증은 23,000원"이 직관적이고, 중복은 배지로 알린다.
- 처리 중인 문서가 하나라도 있으면 목록·통계·오늘 사용량이 4초마다 한 번에(조회 하나로) 갱신된다.
- "처리 중"이 **10분**을 넘긴 문서는 실패로 표시한다.
- 실패 문서에는 사유 한 줄이 보인다(USER_FLOWS.md 7.4의 고정 문장. 암호 걸린 PDF는 별도 사유로 안내). **재시도 버튼은 없다.** 삭제하고 다시 올린다.
- 상세: 원본(이미지는 인라인, PDF는 "원본 열기" 새 탭 링크) + 추출된 거래 표. 중복 배지 옆에 원본 거래가 있는 문서로 가는 "원본 보기" 링크. **읽기 전용**(편집·재분석 없음). 처리 중이면 거래 표 자리에 "분석 중입니다. 잠시 후 다시 확인해 주세요."
- 삭제: 처리 중인 문서는 삭제 버튼이 비활성이다("처리가 끝난 뒤 삭제할 수 있습니다"). 완료·실패 문서를 삭제하면 문서, 그 문서의 거래, 원본 파일을 함께 지운다. 이미 만든 보고서는 그대로 남는다. 삭제해도 하루 사용 횟수는 줄지 않는다(F9).
- 지워진 거래를 "원본"으로 삼아 중복 표시가 붙어 있던 다른 거래는 **전부** 정상 거래로 돌아온다. 돌아온 거래끼리 다시 중복인지는 판정하지 않는다(10.3).

F6은 결번(거래 검색. 10.1).

### F7. 기간 통계
- 기간 선택: **월 단위** + 이전/다음(◀ ▶) 이동 + 기간 라벨("2026년 9월"). 날짜 선택기는 없다.
- **기본 기간은 거래가 있는 가장 최근 달**이다(거래가 하나도 없으면 이번 달). 시연 계정의 시드 날짜가 지나도 첫 화면이 비지 않고, 담당자에게도 자연스럽다. 오늘 이후 날짜의 거래는 기본 달 판정에서 제외한다(Claude가 규칙을 어겨 미래 날짜를 주더라도 첫 화면이 미래의 빈 달로 가지 않게).
- 표시: 그 달의 총액, 거래 건수, 카테고리별 금액과 비율. 그 달 총액이 0 이하이면 비율 칸은 "—".
- 계산 기준
  - 날짜는 **거래일**(못 읽었으면 업로드일). 날짜와 달의 경계는 한국 시간(Asia/Seoul) 기준이다.
  - 금액 미인식 거래와 중복 표시된 거래는 제외. 음수(취소·환불)는 그대로 합산.
  - 통계는 저장하지 않고 볼 때마다 거래에서 계산한다.
- **중복 감지**: 같은 결제가 영수증과 명세서로 두 번 들어오는 경우를 자동 감지한다. 기준은 `거래일 + 합계금액 + 카드 끝 4자리`가 같을 때. 끝 4자리가 없으면 `거래일 + 합계금액 + 가맹점명`. 나중에 들어온 거래에 "중복(집계 제외)" 표시를 붙이고 통계·보고서에서 뺀다.
  - 카드 끝 4자리와 가맹점명이 둘 다 없으면 비교하지 않는다(빈칸끼리 같다고 보지 않는다).
  - "날짜 추정" 거래는 비교에서 제외한다. 날짜가 업로드일이라 우연히 일치할 수 있다.
  - 같은 문서 안의 거래끼리는 비교하지 않는다. 명세서 한 장에 같은 날·같은 금액이 두 번 있으면 실제로 두 번 결제했을 가능성이 높다.
  - 오판(실제로는 다른 결제인데 중복으로 표시됨)을 사용자가 직접 풀 수단은 MVP에 없다. "원본"으로 잡힌 거래의 문서를 삭제하면 표시가 자동으로 풀리지만, 그러면 그 거래가 사라진다. 수동 포함/제외 토글은 2단계(10.1).
- 차트로 보여줄지 숫자 표로 보여줄지는 디자인 단계에서 정한다.

### F8. 보고서 (Claude 작성)
- 사용자가 버튼을 눌러 생성한다. 자동 생성은 없다. **버튼은 통계 구획에 있다**: 보고 있는 달의 **"이 달 보고서 만들기"**.
- 기간: **월간**(달력 월)만.
- 해당 달에 집계 대상 거래가 0건이면 버튼을 비활성화한다.
- 아직 끝나지 않은 달도 만들 수 있다.
- 생성 중 글이 실시간으로 써지는 것이 보인다(스트리밍). 완성되면 저장된다. 완성 전에 화면을 떠나면 저장을 보장하지 않는다(서버가 끝까지 받으면 남을 수 있다). 보고서 목록에 없으면 다시 만든다(사용 횟수는 이미 차감). 새로고침·탭 닫기에는 브라우저 이탈 경고를 띄운다.
- 같은 달을 다시 만들면 덮어쓰지 않고 둘 다 보관한다(생성 시각 표시).
- 입력은 DB에 저장된 거래 데이터만이다. 이미지를 다시 읽지 않는다.
- 보고서 구성(고정 5개 섹션)
  1. 기간 총 지출액과 거래 건수
  2. 카테고리별 금액·비율
  3. 큰 지출 상위 5건
  4. 눈에 띄는 점 (같은 가맹점 반복, 주말·심야 접대비, 같은 금액 중복 등)
  5. 한 문단 총평
- 보고서 화면은 본문 속 링크와 이미지를 그리지 않는다. 영수증에 적힌 문구가 보고서에 섞여 들어와도 누를 것이 생기지 않게 하기 위해서다.
- 보고서 목록: 완료된 것만, 최근 순. 상세에서 본문을 읽고 "복사" 버튼으로 본문을 복사한다.

### F9. 사용량 제한
- 사용자당 **하루 50회**. 문서 분석과 보고서 생성을 합산하고, 실패한 건도 포함한다.
- 차감 시점: 문서는 **업로드 허가(토큰. 브라우저가 파일을 저장소에 올려도 된다는 서버의 승인)를 발급할 때**, 보고서는 **생성을 시작할 때**. 허가를 받은 뒤 업로드가 실패해도 1회로 센다.
- 문서를 지워도 사용 횟수는 줄지 않는다. 지우고 다시 올리기를 반복해 한도를 피할 수 없게 하기 위해서다.
- 한국 시간 자정에 초기화.
- 헤더에 "오늘 사용 n/50"을 항상 보여준다. 한도에 닿으면 업로드 버튼과 보고서 버튼이 비활성화되고 "오늘 한도(50회)를 모두 사용했습니다. 한국 시간 자정에 초기화됩니다."를 보여준다.

F10은 결번(관리자 초대 화면. 10.1).

### F11. 시연 계정과 샘플 데이터
- 일반 사용자 권한의 시연 계정 1개를 관리자가 Clerk 대시보드에서 직접 만든다. 비밀번호는 무작위로 넣고 기록하지 않는다. 포트폴리오에는 주소만 게시한다.
- 들어가는 방법은 랜딩의 **"시연 계정으로 들어가기"** 버튼 하나다. 누르면 서버가 일회용 입장권(sign-in token)을 만들어 로그인시킨다. 비밀번호는 아무도 모른다. 그래서 방문자가 비밀번호를 바꾸거나 오타를 반복해 모든 심사자가 잠기는 일이 없다.
- 가짜 영수증·명세서 이미지 **10건**과 **2026년 8월 월간 보고서 1건**을 미리 채운다. 실제 영수증은 쓰지 않는다(개인정보 없음). 날짜는 **2026-08-01 ~ 2026-09-15로 고정**한다(상대 날짜 아님, 미래 날짜 없음). 통계 첫 화면의 라벨은 "2026년 9월"이다. 같은 결제가 영수증과 명세서 양쪽에 1건 들어 있어 중복 배지가 시연된다. 시드 데이터는 하루 사용 횟수를 쓰지 않는다.
- "샘플로 해보기"의 영수증은 2026년 9월 날짜(9/15 이전)에, 시드와 겹치지 않는 결제로 만든다. **이 고정 샘플은 재시드 직후 첫 번째 클릭에서만 새 결제다.** 두 번째부터는 같은 날짜·금액·카드 끝 4자리라 "중복(집계 제외)" 배지가 붙고 통계가 늘지 않는다. 그때는 배지와 "원본 보기"가 시연이 된다. 자동 재시드·연타 방지는 넣지 않는다.
- 시연 계정에는 사용자 메뉴(Clerk 프로필) 대신 "로그아웃" 버튼만 보인다. Clerk 설정에서도 사용자 계정 삭제를 끈다.
- 심사자가 남긴 삭제·업로드 흔적은 관리자가 시드를 다시 실행해 지운다(수동, 멱등). 자동 재시드는 두지 않는다.
- 시연 계정도 하루 50회 제한을 받는다. 심사자 여러 명이 같은 날 쓰면 한도를 나눠 쓴다.

이 표가 숫자(50회·10분·10MB·20페이지·4초)의 단일 출처다. 다른 문서는 이 값을 인용만 한다.

## 9. 비기능 요구

- **가용성**: 몇 주 동안 아무도 안 써도 심사자가 들어왔을 때 바로 동작해야 한다. 유휴 시 정지되는 서비스는 쓰지 않는다(Supabase 무료 플랜 제외 이유).
- **비용**: 모든 외부 서비스는 무료 플랜. Claude API만 종량 과금이며 하루 50회 제한으로 상한을 둔다.
- **처리 시간**: 문서 1건은 서버 함수 한도 300초 안에 끝나야 한다. 20페이지 제한이 이를 보장한다.
- **민감정보(MVP 범위)**: 카드번호는 끝 4자리만 저장(숫자 4자리가 아니면 비움). 그 외 마스킹·암호화 없음. 원본 파일 링크는 추측 불가능한 주소이지만 링크를 알면 누구나 열 수 있다. 실제 도입에 필요한 보안은 10.2에 기록.
- **테스트**: 핵심 로직은 테스트를 먼저 쓴다(TDD). 화면 흐름은 Cypress 시나리오 3개로 자동화하고, 나머지는 시연 리허설(USER_FLOWS.md 9.1)로 손으로 확인한다. 상세는 ARCHITECTURE 9절.
- **언어**: 한국어 UI. 다국어 없음.
- **화면 테마**: 라이트만. 기기의 다크 설정을 따르지 않고, 앱 안에서 바꾸는 버튼도 없다. 색·글꼴·부품은 `docs/design.md`.

| 자동(예약) 재시드 | 심사자 흔적 정리는 관리자가 수동으로 시드 재실행. cron 청소는 ARCHITECTURE 3절 결정과 충돌 |
| 문서 목록 상한과 "더 보기" | 시연 규모에서 닿지 않음 |
| 대시보드 조회를 목록·통계·사용량 셋으로 나누기 | 조회 하나(`GET /api/dashboard`)로 합쳤다. 폴링 = 요청 1개 |
| 드래그 앤 드롭 업로드 | 클릭 선택으로 충분 |
| "취소" 배지 | 음수 금액 표시로 충분. 배지는 미인식·추정·중복 3종 유지 |
| 미래 날짜를 코드로 보정 | 프롬프트 한 줄("미래 날짜는 null")로 대체. 기본 달 판정에서만 오늘 이후를 제외한다(F7) |
| "샘플로 해보기" 연타 방지 | 1클릭 = 1회이고 헤더에 사용량이 보인다 |
| 스트리밍 끊김(abort) 즉시 감지 | 보고서 목록이 완료만 보여주므로 차이 없음. 10분 규칙으로 충분 |
| `기타` 판정 시 문서 종류 추정 문구 | 스키마 필드 추가. "영수증과 카드 명세서만 읽습니다" 문구로 대체 |
| 폰 화면 꺼짐 시 즉시 재조회 | 화면을 켜면 폴링이 4초 안에 재개된다 |
| 영수증 품목(line items) 추출 | v1 계획의 스키마에는 있었다. 거래 단위(가맹점·합계·카테고리)만 뽑는다. 품목은 통계·보고서에 쓰이지 않는다 |
| 외부 서비스 인터페이스·DI 계층 | v1 ADR-006. 시연 MVP에서는 파일 수만 늘린다. 테스트는 테스트 모드 fixture로(ARCHITECTURE ADR-22) |
| 하루 한도를 환경변수(`DAILY_LIMIT`)로 조절 | 50으로 코드에 고정 |
| 프롬프트 캐시 설정(`cache_control`. 같은 지시문을 다시 보낼 때 요금을 아끼는 기능) | 시연 규모에서 절약이 미미 |
| 사용자별 잠금(advisory lock. 같은 사용자의 후처리를 한 줄로 세우는 DB 장치) | 동시에 끝난 두 건이 중복을 놓치는 경우는 감수(10.3) |
| 보고서 스트림 전용 규약(NDJSON. 글 조각마다 완료·오류 신호를 섞어 보내는 형식) | 스트림이 끝난 뒤 보고서 상태를 한 번 조회해 완료·중단을 판정한다 |
| 파일 앞 바이트(매직 바이트)로 실제 형식 검사 | 확장자로 나누고, 열지 못하면 "파일을 읽을 수 없습니다." |
| 분석용 JPEG 품질 재시도 루프 | 긴 변 2576px 축소 한 번으로 크기 문제가 사라진다 |
| 후처리 전체에 거는 공통 시한 | Claude 호출 시한 240초 + 재시도 없음으로 충분 |
| 보고서 입력 스냅샷(집계와 거래 목록을 한 묶음으로 읽기) | 읽는 사이 삭제가 끼는 경우는 감수(10.3) |

### 10.2 실제 도입 시 필요한 보안
| 항목 | 메모 |
|---|---|
| 원본 파일 비공개 저장 + 기한부(서명) 링크 | 지금은 추측 불가능한 공개 주소 |
| 원본 사진의 EXIF 위치정보 제거 | 지금은 공개 주소로 그대로 노출된다. 브라우저에서 저장소로 바로 올라가 서버가 지울 수 없다 |
| 카드번호·개인정보 마스킹, 저장 시 암호화 | 지금은 끝 4자리만 저장하고 나머지 필드는 평문 |
| 감사 로그(누가 언제 무엇을 봤는지) | |
| 데이터 보존 기간과 삭제 정책 | |
| 접근 기록과 이상 접근 알림 | |
| Anthropic API 데이터 처리 조건 고지의 법적 검토 | 지금은 한 줄 고지만 |
| 사용량 제한의 정확한 동시성 제어 | 지금은 동시에 올리면 한도를 몇 건 넘길 수 있음(감수) |
| Clerk 프로필의 이메일 변경 끄기 | 실제 도입 시 끈다 |
| 테스트 모드 격리 | 테스트 모드는 전용 테스트 DB·Clerk에서만 쓴다. 프리뷰 배포에 `SLIPSCAN_TEST_MODE=1` 금지 |
| 하네스 실행 범위 | 하네스는 검토된 로컬 작업 전용. 원시 출력에 비밀값을 출력하지 않는다 |
| `POST /api/demo-login` 호출 횟수 제한 | 지금은 없음 |

### 10.3 알고 감수하는 것
| 항목 | 내용 |
|---|---|
| 할부 | 명세서 분할액과 영수증 전액이 달라 중복을 못 잡는다 |
| 가맹점명 표기 차이 | 카드 끝4가 없는 현금영수증은 이름이 다르면(유니코드·띄어쓰기 차이 포함) 중복을 못 잡는다 |
| 카톡 경유 재압축 | 추출 정확도가 떨어질 수 있다. 수동 확인 샘플에 포함 |
| 시연 계정 동시 사용 | 서로의 업로드가 섞여 보인다. 안내는 랜딩 고지만 |
| 시연 계정의 부적절한 이미지 | 누가 올리면 다른 방문자에게 보인다. 관리자가 수동으로 재시드 |
| 한 방문자의 한도 소진 | 한 방문자가 50회를 다 쓰면 그날 다른 방문자는 열람만 할 수 있다 |
| 실패한 업로드의 차감 | 업로드 허가를 받은 뒤 실패한 업로드도 1회로 센다. 서버 응답만 유실돼 다시 올리면 2회가 된다 |
| 고정 샘플의 중복 판정 | "샘플로 해보기"는 재시드 후 두 번째 클릭부터 중복으로 판정된다(F11) |
| 동시 후처리 | 같은 사용자의 문서 두 건이 동시에 처리를 마치면 서로를 못 봐 중복을 놓칠 수 있다 |
| 되돌린 거래의 재중복 | 중복의 원본을 지워 정상으로 돌아온 거래끼리 다시 중복이어도 다시 판정하지 않는다 |
| 보고서 입력의 어긋남 | 집계와 거래 목록을 읽는 사이 삭제가 끼면 총액과 목록이 어긋날 수 있다 |
| 처리 중 문서의 직접 삭제 | 화면은 막지만 API를 직접 호출해 처리 중 문서를 지우면 고아 파일이 남을 수 있다 |
| 폴링이 멈춘 뒤의 변화 | 처리 중 문서가 없으면 폴링이 멈춘다. 자정 초기화나 다른 탭의 변화는 새로고침해야 반영된다 |
| 모바일 브라우저 강제 종료 | 모바일 OS가 브라우저를 죽이면 이탈 경고 없이 보고서 스트림이 끊긴다 |
| 보고서 버튼 더블클릭 | 보고서 두 건이 만들어지고 사용량이 2 늘어난다 |
| 문서 속 지시문 | 영수증에 적힌 문장이 형식은 맞지만 사실이 아닌 값을 만들 수 있다. 숫자와 서술은 사람이 확인한다 |
| 아주 큰 입력 | 거래 수백 건짜리 명세서와 거래가 아주 많은 달의 보고서는 실패할 수 있고, 실패도 사용량에 포함된다 |
| 삭제 후 남는 사본 | 원본 파일을 지워도 CDN 캐시와 이미 내려받은 사본이 즉시 사라지는 것은 보장하지 않는다 |
| 저장소 무료 한도 | Blob 고급 작업 월 2,000회·저장 1GB는 주 1회 사용량 확인으로 관찰한다 |
| 아이폰 HEIC | 아이폰이 사진을 HEIC 그대로 넘기면 형식 오류 문구로 막힌다. 수동 확인 항목 |
| CSRF | Clerk 쿠키 SameSite=Lax + JSON 본문만 받는 것으로 충분하다(기록만) |
| Clerk 개발 인스턴스로 공개 | 로그인 화면에 개발 배지가 보이고 가입 계정이 100명으로 제한된다. 운영 인스턴스는 소유 도메인이 필수라 쓰지 않는다(ARCHITECTURE ADR-29) |
| 테스트 계정과 시연 계정의 동거 | Cypress 테스트 계정이 공개 배포와 같은 Clerk 인스턴스에 있다. 데이터는 `user_id`로 갈린다 |

## 12. 용어

| 용어 | 뜻 |
|---|---|
| 문서 | 업로드한 파일 1개. 영수증·카드명세서·기타 |
| 거래 | 문서에서 뽑아낸 결제 1건 |
| 추출 | Claude가 문서를 읽어 거래로 바꾸는 일 |
| 통계 | 월별 총액·카테고리 비율. 저장하지 않고 계산 |
| 보고서 | Claude가 거래 데이터를 바탕으로 쓴 월간 글. 저장됨 |
| 초대 전용 | 관리자가 Clerk 대시보드에서 초대한 이메일만 가입 가능한 상태 |
| 사용 횟수 | 하루 50회 한도에 세는 단위. 문서 업로드 허가 1번 또는 보고서 생성 시작 1번이 1회. 실패해도, 문서를 지워도 줄지 않는다 |
| 업로드 허가(토큰) | 브라우저가 파일을 저장소에 직접 올려도 된다는 서버의 승인. 발급할 때 사용 횟수가 차감된다 |
| 시연 입장권(sign-in token) | 서버가 시연 계정용으로 만드는 일회용 로그인 표. 비밀번호 없이 로그인시킨다 |
| 처리 중 시간 초과 | 10분 넘게 "처리 중"이면 실패로 보는 규칙 |
