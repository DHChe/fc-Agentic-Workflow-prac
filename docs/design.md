디자인 시스템은 PRD만 보고 만들어졌다(USER_FLOWS·ARCHITECTURE는 받지 못함). 그래서 우선순위는 다음과 같다. 기능·범위는 PRD, 화면 문장은 USER_FLOWS 7절, 생김새(색·글꼴·크기·간격)는 이 문서다. 디자인 시스템의 UI 킷에 있는 문장·버튼 이름·메뉴는 참고용이다. 어긋난 곳은 11절에 모았다.

---

## 1. 성격

남의 돈을 다루고 사용자는 숫자를 검산한다. 그래서 차분한 문서 도구처럼 보인다. 종이색 바닥 위의 흰 패널, 1px 선으로만 만드는 깊이, 딥틸 강조색 하나, 자릿수가 맞춰진 숫자. 그라데이션은 쓰지 않는다. 그림자는 팝오버 하나(5절), 움직임은 색 전환과 두 가지 진행 표시(9절)만 쓴다. 한 화면에 업로드·통계·문서·보고서 네 구획이 모두 들어가는 밀도를 목표로 한다. 빈 자리를 여백으로 메우지 않는다.

## 2. 테마

라이트만 쓴다. 기기의 다크 설정을 따르지 않고, 전환 버튼도 없다(ARCHITECTURE ADR-16). 디자인 시스템에 다크 색이 없다.

## 3. 색

### 3.1 앱 토큰

`app/globals.css`의 `:root`에 아래 이름으로 적는다. shadcn/ui에 같은 역할의 이름이 있으면 그 이름을 쓰고, 없으면 확장 토큰을 더한다. Tailwind 클래스는 `--color-<이름>`으로 등록해 `bg-sunken`, `text-strong`처럼 쓴다. 부품 코드에 색 값(#…)을 직접 쓰지 않는다.

shadcn의 `--accent`는 "옅은 강조 면"이다. 디자인 시스템의 `--accent`(딥틸)는 앱에서 `--primary`가 된다. 이름이 같아도 뜻이 다르니 옮길 때 주의한다.

### 3.2 카테고리 8색

도넛과 카테고리 표가 같은 순서를 쓴다. 금액이 큰 카테고리부터 1번 색을 준다. 앱 토큰은 `--chart-1`~`--chart-8`이다(shadcn 기본은 5개라 3개를 더한다).

| 순서 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| 값 | #0d5c5a | #1a7d78 | #37a09a | #6cbcb6 | #a3d5d1 | #4a5a63 | #8b979e | #c7cfd3 |

### 3.3 쓰는 규칙
- 강조색은 primary 버튼, 링크, 업로드 진행률, 보고서 스트리밍 커서, 카테고리 1번 색에만 쓴다.
- 상태색은 넷으로 고정한다: 완료(초록), 처리 중(강조색), 실패·음수 금액(빨강), 확인 필요(노랑). 초록·빨강은 이 뜻으로만 쓴다.

## 4. 글꼴

- **Pretendard Variable** 한 종으로 본문과 숫자를 모두 쓴다(v1.3.9, SIL OFL 1.1, github.com/orioncactus/pretendard). 폰트 파일은 저장소에 넣어 쓰고 CDN에 기대지 않는다. Next.js에서 불러오는 방법은 구현 step에서 공식 문서로 확인한다.
- 대체 글꼴: `-apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Malgun Gothic", sans-serif`.
- 금액·건수·비율·날짜는 `font-variant-numeric: tabular-nums`로 자릿수를 맞춘다. 고정폭(모노) 글꼴은 쓰지 않는다.
- 한글은 `word-break: keep-all`을 전역 기본으로 둔다(단어 중간에서 끊지 않음). 버튼·배지·사용량 카운터·금액·날짜는 줄바꿈하지 않는다.
- 위계는 크기보다 무게(600 / 500 / 400)로 만든다.

| 이름 | 크기 / 줄 높이 | 무게 | 자간 | 쓰임 |

| h1 | 22px / 1.35 | 600 | -0.01em | 제목 |

## 5. 간격·모서리·깊이

| 항목 | 값 |
|---|---|
| 간격 단계 | 2 · 4 · 6 · 8 · 12 · 16 · 20 · 28 · 40px. Tailwind 기본 단위(4px)로 모두 표현된다(2px=0.5, 6px=1.5, 10px=2.5, 22px=5.5) |
| 패널 안쪽 여백 | 위아래 20px, 좌우 22px |
| 표·목록 행 | 위아래 10px |
| 구획 사이 | 28px |
| 본문 최대 폭 | 1180px. 보고서 본문과 로그인은 720px |
| 헤더 높이 | 56px |
| 모서리 | 3px 배지 · 5px 버튼·입력 · 7px 패널 안 영역(업로드 영역·원본 자리) · 10px 패널 · 50% 점 |
| 그림자 | 쓰지 않는다. 깊이는 1px 선과 바탕색 차이로만 만든다. 떠 있는 것(팝오버)만 `0 8px 24px rgba(20,32,31,.10)` |
| 포커스 | 키보드 포커스에만 `box-shadow: 0 0 0 2px #f2f7f7, 0 0 0 3px #1a7d78`(앱 토큰 `--accent`, `--ring`). outline은 없앤다 |

shadcn 부품의 모서리·높이 클래스는 이 표에 맞게 고친다. shadcn 기본 계산식(`--radius`에서 더하고 빼기) 대신 위 값을 직접 적는다.

## 6. 부품

### 6.1 버튼

| 종류 | 바탕 | 테두리 | 글자 | 눌림 바탕 |
|---|---|---|---|---|
| primary | #0d5c5a | #0d5c5a | #ffffff | #094442 (테두리도) |
| secondary | #ffffff | #e4e8e7 | #14201f | #eff2f1 |
| ghost | 투명 | 투명 | #0d5c5a | #f2f7f7 |
| danger | #ffffff | #e4e8e7 | #a8342f | #fdf6f5 |
| 비활성(모든 종류) | #eff2f1 | #e4e8e7 | #a9b3b2 | — |

- 크기: md 높이 38px·좌우 20px·14px(기본) / sm 높이 30px·좌우 12px·13px(표 행·패널 머리) / xs 높이 24px·좌우 8px·11px(배지 옆).
- 공통: 글자 무게 500, 모서리 5px, 아이콘과 글자 사이 8px, 바탕·테두리 색만 0.1초 linear로 바뀐다. 눌려도 크기는 변하지 않는다. hover는 눌림보다 약하게 같은 방향으로 바꾸고 따로 정하지 않는다.
- danger는 shadcn의 destructive(빨간 바탕)가 아니라 흰 바탕 + 빨간 글자다.
- primary는 한 구획에 하나까지 둔다(11절).
- 못 누르는 상황(처리 중 삭제, 한도 초과, 거래 0건인 달의 보고서)은 버튼을 숨기지 않고 비활성으로 두고, 이유를 옆에 한 줄로 쓴다.

### 6.2 배지

USER_FLOWS 6절의 배지 6종을 다섯 가지 색 조합으로 그린다. 금액 미인식과 날짜 추정은 같은 색이고 글자로 구분한다.

| 배지 | 글자 | 바탕 | 테두리 |
|---|---|---|---|
| 처리 중 | #0d5c5a | #f2f7f7 | #d8e2e1 |
| 완료 | #1f7a4d | #f4faf7 | #cfe3d8 |
| 실패 | #a8342f | #fdf6f5 | #eed4d2 |
| 금액 미인식 · 날짜 추정 | #8a6108 | #fdf8ec | #efe3c4 |
| 중복(집계 제외) | #7d8a89 | #f7f8f7 | #e4e8e7 |

- 공통: 높이 21px, 좌우 6px, 모서리 3px, 1px 테두리, 11px·무게 500, 줄바꿈 없음.
- 거래 표의 배지 위치(문서 상세 템플릿 기준): 날짜 추정은 거래일 아래, 중복은 가맹점 아래에 "원본 보기" 링크와 함께, 금액 미인식은 금액 칸 "—" 아래. 문서 상세의 상태 배지는 왼쪽 열 맨 위.

### 6.3 금액·숫자
- 금액은 줄이지 않는다. 천 단위 쉼표와 "원"을 붙인다(1,126,600원). "약 113만원"처럼 쓰지 않는다.
- 음수 금액(취소·환불)은 빨강(#a8342f)으로 "-8,900원"처럼 쓴다.
- 비율은 소수 첫째 자리까지(36.6%).
- 표 안 금액은 오른쪽 정렬.

### 6.4 헤더
- 높이 56px, 흰 바탕, 아래 1px 선.
- 왼쪽: 글자 로고. 로고 파일이 없으므로 "SlipScan"을 Pretendard 600, 자간 -0.02em으로 쓰고 앞에 딥틸 점 하나를 둔다. 심볼을 새로 그리지 않는다.
- 오른쪽: "오늘 사용 n/50"(숫자 강조)과 사용자 메뉴. 시연 계정은 로그아웃 버튼만(PRD 5절).

### 6.5 구획과 패널
- 구획 = 제목줄(h2 + 오른쪽 보조 설명이나 버튼) + 흰 패널.
- 패널: 흰 바탕, 1px `--border`, 모서리 10px, 안쪽 여백 20/22px.
- 표·목록: 행 위아래 10px, 행 사이 `--border-soft` 선, 열 이름은 caption 크기 + muted 글자, 표 안은 13px. 행 전체가 누를 수 있는 영역이다.

### 6.6 업로드 영역
- 패널 안에 `--sunken` 바탕·모서리 7px 영역. 아이콘(24px) + 안내 한 줄 + 오른쪽에 "올리기"(primary)와 "샘플로 해보기"(secondary).
- 흐름은 USER_FLOWS UC-05를 따른다: 영역을 눌러 파일을 고른다 → 영역 안에 파일명·크기를 보여준다 → "올리기". 형식·크기 오류일 때 "올리기"는 비활성이고 USER_FLOWS 7.2 문구를 한 줄로 보여준다(UC-05 E1·E2).
- 영역 아래에 형식·크기 제한 한 줄(caption).
- 업로드 중에는 강조색 진행률 바를 보여준다.

### 6.7 월 통계
- 월 이동(이전·다음 화살표 사이에 "2026년 9월")과 "이 달 보고서 만들기"(primary)가 구획 제목줄에 있다.
- 패널 안 왼쪽: 월 총액(amount-lg) + 보조 설명 + 도넛. 오른쪽: 카테고리 표(카테고리 색 점 · 이름 · 금액 · 비율).
- 도넛: 지름 200px, 두께 26px, 조각 사이 2px 틈, 12시 방향부터 시계 방향. 합계가 0이면 `--border` 색 빈 원.
- 차트는 도넛 하나뿐이다. 막대·추세선은 없다.

### 6.8 보고서 화면
- 본문 폭 720px. 스트리밍 중에는 글 끝에 강조색 커서를 둔다.
- 본문 속 링크와 이미지는 그리지 않는다(PRD F8).

### 6.9 빈 상태·안내 줄
- 빈 목록은 여백으로 두지 않고 아이콘(24px) + 문장으로 채운다. 문장은 USER_FLOWS 7절.
- 한도 초과·실패 사유는 해당 구획 안에 한 줄 안내로 보여준다. 문장은 USER_FLOWS 7절.

## 7. 화면 배치

### 7.1 대시보드
- 한 단(세로)으로 구획을 쌓는다: 업로드 → 월 통계 → 문서 목록 → 보고서 목록(USER_FLOWS UC-04 순서). 구획 제목 문장은 USER_FLOWS 7절.
- 월 통계 패널만 안에서 두 열(왼쪽 총액·도넛 약 260px, 오른쪽 카테고리 표)이다.

### 7.2 문서 상세
- 위: 대시보드로 돌아가는 링크(chevron-left 아이콘 + 글자), 제목줄(문서 종류 + 업로드 시각 caption, 오른쪽 끝에 삭제 danger 버튼).
- 아래 두 열. 왼쪽 좁은 열 패널: 상태 배지 → 원본 자리(3:4, 모서리 7px, `--sunken` 바탕) → 문서 합계(amount-md) → 합계 기준 안내(caption) → "원본 열기" 링크. 오른쪽 넓은 열 패널: 거래 표.
- 원본 이미지는 보정·필터 없이 그대로 보여준다. PDF는 원본 자리에 "원본 열기" 링크만 둔다(USER_FLOWS UC-09).

### 7.3 반응형

| 구간 | 동작 |
|---|---|
| 폰 < 768px | 헤더는 로고 + 사용량 + 사용자 메뉴(시연 계정은 로그아웃)만. 모든 구획 한 단. 월 통계는 총액 → 도넛 → 카테고리 표 순으로 쌓는다. 문서 상세는 왼쪽 열 → 거래 표 순 |
| 태블릿 768–1024px | 월 통계는 도넛 위, 표 아래. 문서 목록은 모든 열 유지 |
| 데스크톱 1024–1180px | 기준 배치 |
| 넓은 화면 > 1180px | 본문 폭 1180px 고정, 바깥 여백만 늘어난다 |

- **폰에서 표를 접는 방식은 열 숨김이다.** 카드형으로 바꾸거나 행을 펼치지 않는다. 폰에서 어떤 열을 남기고 숨길지는 USER_FLOWS 4.1 표를 따른다.
- 누르는 영역은 최소 38px(표 안 30px, 배지 옆 24px).

## 8. 아이콘

- Lucide 세트를 쓴다. 앱에서는 `lucide-react`(shadcn/ui 기본 아이콘과 같은 세트). 선 2px, 24px 격자.
- 크기: 14px(표 안·작은 버튼), 16px(기본), 20px(랜딩 특징), 24px(업로드 영역·빈 상태).
- 쓰는 글리프: upload, receipt-text, file-text, chevron-left, chevron-right, loader, copy, arrow-right, info, triangle-alert, circle-alert, inbox, file-question, scan-line, chart-pie.
- 목록 행·배지·표 칸에는 아이콘을 넣지 않는다(정렬이 흐트러지고 읽기 느려진다).
- 이모지와 유니코드 도형(▶, ✓ 등)을 쓰지 않는다. 월 이동 화살표도 Lucide를 쓴다.
- SVG를 손으로 그리지 않는다. 예외는 도넛 원호 하나다.

## 9. 움직임

- 색 전환 0.1초 linear만 쓴다.
- 움직이는 것은 둘뿐이다: 업로드 진행률 바, 보고서 스트리밍 커서. 둘 다 "지금 진행 중"을 알린다.
- 숫자 카운트업, 패널 등장 효과, 스크롤 연동 효과는 쓰지 않는다.

## 10. 문구 톤

문장 자체는 USER_FLOWS 7절에서 글자 그대로 가져온다(`lib/messages.ts`). 이 절은 7절에 없는 문장을 새로 써야 할 때만 적용한다.
- 친절하되 사실부터. 사과·감탄·과장·이모지·느낌표 없음.
- 사용자에게는 "~해 주세요", 시스템이 한 일은 "집계에서 뺐습니다"처럼 분명히.
- 버튼은 동사로 2~5자 또는 짧은 구. "확인", "제출", "여기를 클릭"은 쓰지 않는다.
- 영어 UI 용어를 섞지 않는다(리포트 → 보고서).

## 11. 디자인 시스템과 다르게 정한 것

| 항목 | 디자인 시스템 | 이 문서 | 이유 |
|---|---|---|---|
| 헤더 메뉴 | 문서 상세 템플릿 헤더에 "대시보드·문서·보고서" 탭 | 만들지 않는다 | PRD 5절 헤더는 사용량과 로그아웃뿐. 문서·보고서 목록은 대시보드 안에 있다 |
| 랜딩 | UI 킷 랜딩이 스크롤형, 특징 4개 | 따르지 않는다. PRD F1(한 화면, 특징 3개)이 기준 | PRD 우선. 랜딩 문구는 12절에서 미정 |
| 버튼·빈 상태 문장 | UI 킷에 자체 문장("파일 선택" 등) | USER_FLOWS 7절 문장 | 디자인 시스템은 USER_FLOWS를 받지 못했다 |
| 폰에서 남기는 열 | 거래 표는 거래일·가맹점·합계만 | USER_FLOWS 4.1(배지 포함) | USER_FLOWS가 열 우선순위의 출처 |
| 카테고리 색 | readme에 "딥틸 4 + 중성 4" | 부품 코드의 실제 8색(3.2) | 코드 값이 실제로 그려지는 색 |
| 구획당 primary 개수 | readme·Button 계약은 "1~2개", Button 사용 설명은 "한 구획에 둘 이상 두지 않는다"로 서로 다르다 | 한 구획에 하나까지 | 대시보드·문서 상세 템플릿이 실제로 구획마다 하나만 쓴다 |
| 업로드 버튼 | "파일 선택"(primary) 한 번으로 올림 | 파일 고르기 → "올리기"(primary) 두 단계 | USER_FLOWS UC-05·7.8 |
| 아이콘 불러오기 | CDN(`lucide-static`) | `lucide-react` 패키지 | 같은 세트. 앱은 shadcn/ui와 맞춘다 |
| 다크 테마 | 미구현("나중에") | 만들지 않는다 | ADR-16 |
