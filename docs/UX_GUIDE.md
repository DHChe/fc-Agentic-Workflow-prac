## 1. 시연 임팩트의 정의

임팩트는 꾸밈에서 나오지 않는다. 그라데이션·글로우는 금지 목록에 있고(UI_GUIDE), 패널 등장 효과를 포함해 움직임은 둘만 남겼다(design.md 9절). SlipScan의 임팩트는 **심사자가 5분 안에 "아, 이게 되는구나"를 여섯 번 느끼는 것**이다. 화면이 할 일은 그 여섯 장면마다 주인공 하나가 또렷이 보이게 하고, 나머지는 한 걸음 물러나게 하는 것이다.

### 1.1 여섯 장면 (USER_FLOWS J1 기준)

| 장면 | J1 순서 | 심사자가 느껴야 하는 것 | 주인공(하나) | 조연 | 장면을 망치는 것 |
|---|---|---|---|---|---|
| A 랜딩 | 1 (0:00) | 5초 안에 무엇을 하는 앱인지 안다 | 제목 한 줄(display) | "시연 계정으로 들어가기"(primary) | 고지 두 줄이 제목보다 눈에 띔. 스크롤이 생김 |
| B 채워진 대시보드 | 3 (0:20) | 누가 이미 쓰고 있는 화면이다 | 월 총액(amount-lg. 화면에서 가장 큰 글자) | 도넛·카테고리 표, 문서 10건 | 총액이 다른 글자에 묻힘. 로딩 중 빈 화면 |
| C 문서 상세 | 4 (0:45) | 사진에서 이걸 뽑았고 중복도 잡는다 | 나란히 놓인 원본과 거래 표 | "중복(집계 제외)" 배지 + "원본 보기" | 원본이 너무 작아 표와 견줄 수 없음. 삭제 버튼이 시선을 끔 |
| D 올리기 → 완료 | 5~8 (1:00~2:30) | 기다리지 않아도 되고, 숫자가 살아 있다 | 목록 맨 위 새 행의 배지가 "처리 중"에서 "완료"로 | 진행률 바, 월 총액의 변화, 오늘 사용 n/50 | 누른 뒤 1초 넘게 아무 변화 없음 |
| E 보고서 쓰기 | 9 (3:00) | 글이 실시간으로 써진다(시연의 하이라이트) | 흐르는 글과 강조색 커서 | 완료 문구, "열기" | 글이 화면 밖에서 흐름. 버튼을 눌렀는데 어디를 봐야 할지 모름 |
| F 보고서 읽기 | 10 (3:40) | 이걸 그대로 보내도 되겠다 | 다섯 섹션의 소제목 위계 | "복사"와 복사 확인 한 줄 | 소제목과 본문이 같은 크기라 한 덩어리로 보임 |

화면을 고칠 때는 먼저 "어느 장면의 주인공을 돕는가"를 답한다. 어느 장면에도 닿지 않는 꾸밈은 넣지 않는다(PRD 2절 범위 판단 기준과 같다).

### 1.2 임팩트를 만드는 것과 만들지 않는 것

| 만든다 | 만들지 않는다 |
|---|---|
| 첫 화면이 이미 차 있다(시드 10건, 거래가 있는 최근 달) | 빈 화면에서 시작하는 온보딩 |
| 가장 중요한 숫자가 가장 크다 | 모든 숫자를 같은 크기로 나열 |
| 누르면 1초 안에 무언가 바뀐다 | 숫자 카운트업, 패널 등장 효과(design.md 9절) |
| 진짜 진행만 움직인다(진행률 바, 스트리밍 커서) | 기다림을 가리는 장식 애니메이션 |
| 입력 없는 입장, 파일 없는 업로드("샘플로 해보기") | 가이드 투어, 툴팁 연쇄, 안내 모달. 화면 자체가 설명이어야 한다 |
| 원본을 옆에 두고 검산할 수 있다 | "AI가 했습니다" 배지(UI_GUIDE) |

## 2. 일곱 원칙

원칙마다 쉬운 말 한 줄, SlipScan 규칙, 점검 질문을 둔다. 괄호는 규칙의 출처다.

### 2.1 계층 구조

신문 1면처럼, 제일 중요한 것이 제일 크고 진하다.

**화면마다 주인공은 하나다.**

| 화면 | 1순위 | 2순위 | 3순위 | 가장 흐리게 |
|---|---|---|---|---|
| 랜딩 | 제목(display) | "시연 계정으로 들어가기" | 특징 3개 | 고지 두 줄(caption) |
| 대시보드 | 월 총액(amount-lg) | 구획 제목(h2), "이 달 보고서 만들기" | 표의 값(cell, strong) | 열 이름·시각·기준 설명(caption, muted) |
| 문서 상세 | 문서 종류(h1) | 원본과 거래 표 | 문서 합계(amount-md) | 합계 기준 안내(caption) |
| 보고서 | 달(h1) | 섹션 소제목(h2·h3) | 본문(body) | 만든 시각·사용 모델(caption) |

- 위계는 크기보다 무게(600/500/400)로 만든다. 크기는 design.md 4절 표의 단계만 쓰고 새 크기를 만들지 않는다.
- 34px은 한 화면에 한 번만 쓴다. 대시보드에서는 월 총액, 랜딩에서는 제목이다.
- PC에서 대시보드를 열면 스크롤 없이 월 총액과 "이 달 보고서 만들기"가 보여야 한다. 업로드 구획의 높이를 늘려 통계를 밀어내지 않는다. 이 줄은 다른 문서에 없고 이 문서가 더한 확인 기준이다(2026-09-19 공개 배포는 1512×786 창에서 통계 패널 끝까지 들어온다).
- primary 버튼은 한 구획에 하나까지다(design.md 6.1). 파일을 고르기 전에는 "올리기"가 비활성이므로, 막 들어온 심사자의 눈에 강조색 버튼은 "이 달 보고서 만들기" 하나다. 이 상태를 지킨다.
- 라벨은 흐리게, 값은 진하게 쓴다. 열 이름과 "문서 합계" 같은 이름표는 muted, 금액과 가맹점은 strong이다.

점검: 눈을 가늘게 뜨고 화면을 흐리게 봤을 때 1순위가 먼저 보이는가. 1순위와 2순위를 가려도 화면의 뜻이 통하는가(통하면 위계가 뒤집힌 것이다).

### 2.2 점진적 공개

한 번에 다 말하지 않고, 필요해진 순간에 그 자리에서 말한다.

- 층은 둘뿐이다. 대시보드(요약) → 상세(세부)(UC-04, UC-09). 폰에서 표를 접을 때도 행 펼치기 대신 열 숨김을 쓴다(design.md 7.3). 모달 안의 모달 같은 세 번째 층은 만들지 않는다.
- 문서 목록 행에는 PRD F5의 다섯 칸만 둔다. 거래 내용은 상세에서 본다.
- 업로드는 두 걸음이다. 파일을 고른 뒤에야 파일명·크기·형식 오류가 보이고, 그다음이 "올리기"다(UC-05).
- 아직 모르는 값은 "—"로 둔다(USER_FLOWS 7.8). 0이나 빈칸으로 두면 "0원"과 "아직 모름"이 섞인다.
- 실패 사유, 한도 안내, 비활성 이유는 그 상황이 됐을 때 그 구획 안에 한 줄로 보인다(design.md 6.9). 미리 경고문을 깔아 두지 않는다.
- 지금 어디쯤인지 항상 알린다. 업로드는 진행률 바 → "처리 중" → "완료", 보고서는 "보고서 작성 중"과 커서 → 완료 문구, 하루 한도는 헤더의 "오늘 사용 n/50"이다.
- 숫자의 기준을 밝히는 문장(통계의 제외 기준, 문서 합계의 기준)은 그 숫자 바로 아래 caption으로 둔다. 별도 도움말 화면은 없다.

점검: 이 정보는 지금 이 순간 필요한가, 아니면 다음 화면의 것인가. 사용자가 "지금 뭐가 진행 중이지?"를 물을 틈이 있는가.

### 2.3 일관성

같은 뜻이면 같은 모양, 같은 말을 쓴다. 모양이 달라지면 사용자는 뜻도 달라졌다고 읽는다.

- 상태색은 넷(완료·처리 중·실패·확인 필요), 배지는 다섯 색 조합, 버튼은 네 종류 × 세 크기뿐이다(design.md 3.3, 6.1, 6.2). 새로 만들지 않는다.
- 같은 상황에는 같은 틀을 쓴다.

| 상황 | 틀 | 출처 |
|---|---|---|
| 지금은 못 누르는 버튼 | 숨기지 않고 비활성 + 이유 한 줄을 옆에 | design.md 6.1 |
| 빈 목록 | 아이콘 24px + 문장 | design.md 6.9 |
| 오류·안내·완료 알림 | 해당 구획 안의 한 줄(`NoticeLine`). 토스트·전역 배너를 새로 만들지 않는다 | design.md 6.9 |
| 되돌릴 수 없는 동작 | 확인 대화. 앱에서는 문서 삭제 하나뿐이다 | USER_FLOWS 7.6 |
| 상세에서 돌아가기 | 왼쪽 위 "대시보드" 링크 하나 | design.md 7.2 |

- 문장은 `lib/messages.ts`에서만 가져온다. 같은 것을 두 이름으로 부르지 않는다. 문서·거래·보고서(PRD 12절), 원본·올리기(USER_FLOWS 7.8)를 쓰고 "리포트", "업로드하기", "파일 목록" 같은 다른 이름을 섞지 않는다.
- 금액·비율의 표기는 한 가지다(design.md 6.3). 금액은 줄이지 않고, 음수는 "-"와 빨강을 함께 쓴다. 날짜 표기도 화면마다 새로 만들지 않고 `lib/format.ts` 한 곳에서만 나온다.
- 기존 틀에서 벗어나야 하면 design.md 11절처럼 이유를 표로 남긴다. 이유를 못 적겠으면 벗어나지 않는다.

점검: 이 화면에만 있는 모양·말이 있는가. 있다면 이유가 적혀 있는가.

### 2.4 대비

형광펜은 아껴 써야 표시가 된다.

- 강조색(딥틸)은 다섯 곳에만 쓴다: primary 버튼, 링크, 업로드 진행률, 스트리밍 커서, 카테고리 1번 색(design.md 3.3). 제목이나 아이콘을 강조색으로 칠하지 않는다.
- 한 구획에서 가장 진한 덩어리는 하나다. 월 통계에서는 총액, 업로드에서는 (파일을 고른 뒤의) "올리기"다.
- 삭제는 Figma 예시(빨간 바탕 버튼)와 다르게 약하게 둔다. 흰 바탕에 빨간 글자다(design.md 6.1). 삭제는 시연 여정에 없는 동작이고 시연 계정을 어지르는 동작이라 시선을 끌지 않는다. 위험을 알리는 일은 확인 대화가 맡는다.
- 초록과 빨강은 상태의 뜻으로만 쓴다. 꾸밈으로 쓰면 "완료"와 "실패"의 신호가 약해진다.
- 비활성 버튼은 확실히 흐리게 두되, 옆의 이유 문장은 흐리게 하지 않는다. 그 문장은 읽혀야 한다.

점검: 강조색이 한 화면에서 세 군데 넘게 눈에 들어오는가(그렇다면 하나도 강조되지 않은 것이다).

### 2.5 접근성

잘 안 보이는 사람, 마우스를 못 쓰는 사람, 밝은 회의실 빔프로젝터로 보는 심사자에게도 같은 정보가 가야 한다.

기준은 WCAG AA다. 일반 글자 4.5:1, 큰 글자(24px 이상, 또는 굵은 18.66px 이상) 3:1, 글자가 아닌 UI 요소 3:1. 아래는 design.md 3절의 색으로 계산한 값이다(2026-09-19).

| 조합 | 대비 | 판정 |
|---|---|---|
| 제목·금액 #14201f / 흰 패널 | 16.72 | 통과 |
| 본문 #42504f / 흰 패널 · 바닥 | 8.43 · 7.92 | 통과 |
| primary 버튼의 흰 글자, 링크 #0d5c5a | 7.79 | 통과 |
| 배지: 처리 중 · 실패 · 확인 필요 · 완료 | 7.21 · 6.15 · 5.22 · 5.03 | 통과 |
| 음수 금액·danger #a8342f / 흰 | 6.57 | 통과 |
| 포커스 링 #1a7d78 / 흰 | 4.94 | 통과(3:1 기준) |
| **캡션·열 이름 muted #7d8a89 / 흰 패널 · 바닥** | **3.58 · 3.36** | **미달**(7절 제안 1) |
| **"중복(집계 제외)" 배지 #7d8a89 / #f7f8f7** | **3.36** | **미달**(7절 제안 1) |
| 비활성 글자 #a9b3b2 / #eff2f1 | 1.91 | 기준 적용 제외(비활성 요소) |
| 도넛 3·4·5·7·8번 색 / 흰 | 3.15 · 2.21 · 1.62 · 2.99 · 1.58 | 도넛만으로는 미달. 아래 규칙으로 보완 |

- 색만으로 말하지 않는다. 배지에는 글자가 있고, "금액 미인식"과 "날짜 추정"은 같은 색이라 글자로 갈린다. 음수 금액은 빨강과 "-" 기호를 함께 쓴다. 도넛은 옆의 카테고리 표가 같은 정보를 글자로 주므로, 도넛에만 실린 정보를 만들지 않는다.
- 통과하지 못한 muted 색에는 없어도 뜻이 통하는 정보만 싣는다. 꼭 읽혀야 하는 문장(실패 사유, 비활성 이유, 한도 안내)은 본문색이나 상태색으로 쓴다.
- 모든 동작은 키보드(Tab, Enter, Space)로 된다. 포커스 링은 design.md 5절의 값 하나다. 행 전체가 링크인 표는 행에 포커스가 보여야 한다.
- 비활성 버튼은 Tab으로 닿지 않는다. 그래서 이유를 툴팁에 넣지 않고 옆에 글자로 둔다(2.3의 틀).
- 아이콘만 있는 버튼에는 화면낭독기용 이름을 붙인다. 월 이동 화살표의 이름은 USER_FLOWS 7.8에 있다. 꾸밈 아이콘은 `aria-hidden`이다.
- 눈으로만 보이는 변화를 화면낭독기에도 알린다. 안내 한 줄(업로드 결과, 보고서 완료·중단, 삭제 완료, 한도 도달)은 `role="status"`로 읽히게 한다. 보고서 상세의 복사 확인이 이미 이 방식이다.
- 누르는 영역은 최소 38px(표 안 30px, 배지 옆 24px)이다(design.md 7.3).
- 움직임은 둘뿐이지만, 기기의 "동작 줄이기" 설정에서는 커서의 깜빡임을 멈춘다(`motion-reduce`). 진행률 바는 진행 정보라 그대로 둔다.
- 글자를 200%로 키워도 가로 스크롤 없이 읽혀야 한다. 줄바꿈 금지는 design.md 4절에 적힌 요소(버튼·배지·사용량·금액·날짜)에만 건다.

점검: 마우스 없이 J1의 1~10번을 끝낼 수 있는가. 화면을 흑백으로 바꿔도 상태가 구분되는가.

### 2.6 근접성

붙어 있으면 한 식구로 읽힌다. 떨어져 있으면 남으로 읽힌다.

- 간격은 관계의 거리다. 구획 사이 28px > 패널 안쪽 20/22px > 표 행 10px > 이름표와 값 사이 4~8px. 가까운 관계일수록 좁다. 값은 design.md 5절의 단계만 쓴다.
- 이유는 그 버튼 옆에(design.md 6.1), 배지는 그 값 아래에 둔다(design.md 6.2). 날짜 추정은 거래일 아래, 중복은 가맹점 아래, 금액 미인식은 금액 칸 "—" 아래다.
- "원본 보기"는 중복 배지 바로 옆이다. "무엇과 중복인가"라는 질문의 답이기 때문이다.
- "이 달 보고서 만들기"는 월 통계 제목줄, 달 이름 바로 옆에 있다(USER_FLOWS G-5). 그래서 "어느 달의 보고서인가"를 따로 묻지 않아도 된다.
- 위험한 동작은 떨어뜨린다. 삭제는 제목줄 오른쪽 끝에 혼자 두고, 다른 버튼과 나란히 붙이지 않는다(Figma의 "종료 버튼은 따로" 예시와 같은 이유).
- 도넛과 카테고리 표는 한 패널 안에 두고 같은 색 점으로 잇는다(design.md 6.7).
- 결과는 원인 가까이에 나타나야 한다. 버튼과 결과 자리가 떨어져 있으면(보고서 버튼은 통계 구획, 글이 흐르는 자리는 보고서 구획) 누른 즉시 결과 자리로 화면을 옮긴다.

점검: 설명 없이 덩어리만 보고도 무엇이 무엇에 속하는지 알 수 있는가.

### 2.7 정렬

줄이 맞으면 숫자는 저절로 비교된다. 담당자는 숫자를 검산하는 사람이다(design.md 1절).

- 세로 기준선은 하나다. 헤더의 로고, 구획 제목, 패널이 같은 왼쪽 선에서 시작한다(본문 폭 1180px). 보고서 본문과 로그인만 720px이다(design.md 5절).
- 금액·건수·비율은 오른쪽 정렬 + `tabular-nums`다. 열 이름도 값과 같은 쪽으로 맞춘다.
- 글자는 왼쪽 정렬이다.
- 목록 행·배지·표 칸에 아이콘을 넣지 않는다(design.md 8절). 아이콘 하나가 열의 시작선을 흐트러뜨린다.
- 값이 "—"이든 "384,100원"이든 열의 폭과 정렬이 변하지 않아야 한다. 4초 폴링으로 값이 채워질 때 표가 출렁이면 안 된다.
- 폰에서는 열을 숨길 뿐 카드로 바꾸지 않는다(design.md 7.3). 남은 열의 정렬은 PC와 같다.

점검: 금액 열의 "원" 글자가 세로로 한 줄에 서는가. "처리 중" 행이 "완료"로 바뀔 때 다른 행이 움직이는가.

## 3. 안내 설계

### 3.1 누르면 무엇이 보여야 하는가

규칙은 셋이다. (1) 누르면 1초 안에 화면의 무언가가 바뀐다. (2) 1초 넘게 걸리는 일은 진행 중임을 보여준다. (3) 10초 넘게 걸리는 일은 기다리지 않아도 된다고 알려준다.

| 동작 | 1초 안에 | 진행 중 | 끝났을 때 | 실패했을 때 |
|---|---|---|---|---|
| 시연 계정으로 들어가기 | 버튼이 눌린(비활성) 상태가 된다 | 같음 | 대시보드 | 랜딩에 USER_FLOWS 7.3 시연 로그인 실패 한 줄 |
| 올리기 · 샘플로 해보기 | 두 버튼 비활성 + 진행률 바 | 진행률 바 | 업로드 완료 안내 한 줄(`MESSAGES.ui.uploadDone`. 떠나도 된다는 말 포함) + 목록 맨 위 "처리 중" 행 + "오늘 사용" +1 | 7.2·7.3 한 줄. 고른 파일은 그대로 남는다 |
| 분석 기다리기 | "처리 중" 배지, 모르는 칸은 "—" | 4초마다 목록·통계·사용량이 함께 갱신 | 배지 "완료", 건수·합계, 같은 주기에 월 총액 | "실패" 배지 + 사유 한 줄(7.4) |
| ◀ ▶ 월 이동 | 달 이름과 숫자가 함께 바뀐다 | — | — | — |
| 이 달 보고서 만들기 | 버튼 비활성 + 보고서 구획으로 이동 + "보고서 작성 중" + 커서 | 글이 흐른다 | 7.5 완료 문구 + "열기" + 보고서 목록 맨 위 | 7.5 중단 문구(부분 글은 남는다) 또는 7.3 오류 문구 |
| 복사 | 복사 확인 한 줄 | — | — | 오류 한 줄 |
| 삭제 | 확인 대화(7.6) | 대화의 두 버튼 비활성 | 대시보드 + 7.6 완료 문구 | 오류 한 줄 |
| 목록 행 → 상세 | 상세 화면의 틀이 보인다 | 같음 | 내용이 채워진다 | 404 화면(UC-22) |

### 3.2 상태마다 무엇을 답해야 하는가

막다른 길을 만들지 않는다. 어떤 상태에서든 화면은 "지금 무슨 일인가"와 "이제 무엇을 하면 되는가"에 답한다.

| 상태 | 사용자가 속으로 묻는 것 | 화면의 답 | 출처 |
|---|---|---|---|
| 빈 대시보드(첫날) | 뭘 해야 하지? | 업로드 구획이 맨 위, 빈 상태 문장이 첫 행동을 가리킨다 | UC-04 V1, 7.1 |
| 처리 중 | 멈춘 건가? 기다려야 하나? | 배지 + "—" + 떠나도 된다는 안내. 돌아오면 최신 상태 | UC-08 |
| 실패 | 왜? 어떻게 하지? | 사유 한 줄. 암호 PDF는 푸는 법까지. 다시 하려면 삭제 후 다시 올린다 | UC-10, 7.4 |
| 거래 0건 | 고장인가? | 무엇만 읽는지 알려주는 문장 + 원본은 보인다 | UC-09 V3 |
| 중복 | 왜 통계에 안 들어갔지? 무엇과 겹치지? | 배지 이름이 "집계 제외"를 말하고, "원본 보기"가 상대를 보여준다 | UC-09 V6 |
| 금액 미인식 · 날짜 추정 | 무엇을 못 읽었지? | 그 값 자리의 배지 | UC-09 V4·V5 |
| 한도 도달 | 고장인가? 언제 풀리지? | 버튼 비활성 + 자정 초기화를 알리는 7.3의 429 문장. 열람은 그대로 된다 | UC-17 |
| 보고서 중단 | 저장됐나? | 부분 글은 남기고 7.5 중단 문장. 목록에 없으면 다시 만든다 | UC-15 E5 |
| 없는 문서·보고서 | 어디로 가지? | 7.3 문장 + 대시보드 링크 | UC-22 |

### 3.3 심사자를 위한 길 안내

심사자는 설명서를 읽지 않는다. 길 안내는 글이 아니라 배치가 한다.

- 첫 화면이 곧 설명이다. 채워진 통계와 문서 10건이 "이런 걸 하는 앱"이라고 말한다(장면 B).
- 다음 행동은 항상 하나만 눈에 띈다. 랜딩에서는 "시연 계정으로 들어가기", 대시보드에서는 "이 달 보고서 만들기"와 (파일이 없는 사람을 위한) "샘플로 해보기"다.
- 기다리는 시간에 볼 것이 있다. 처리 중에도 목록·통계·시드 보고서는 그대로 열린다(J1 6번).
- 구획 순서가 곧 사용 순서다: 업로드 → 통계 → 문서 → 보고서(UC-04). 순서를 바꾸지 않는다.

## 4. Figma 프로 팁 네 가지의 적용

| 팁 | SlipScan에서 |
|---|---|
| 사용자 관점에서 순서를 짠다 | 구획 순서 = J1의 행동 순서. 새 요소를 넣을 때는 J1의 몇 번째 행동에 쓰이는지부터 적는다 |
| 간편하게. 좋은 인터페이스는 눈에 띄지 않는다 | 모든 누름에 3.1의 반응을 준다. 화면 사이 이동 방식은 하나(행 클릭으로 들어가고 "대시보드"로 나온다) |
| 단축 기능을 둔다 | SlipScan의 단축 기능은 셋이다: 입력 없는 시연 입장, "샘플로 해보기", 보고서 "복사". 검색은 만들지 않는다(PRD 10.1). 키보드 단축키는 애초에 계획에 없다 |
| 테스트한다 | 5절 점검표 + USER_FLOWS 9.1 리허설(시간을 잰다. H1). 공개 뒤에는 H2의 확인 방법대로 심사자 2~3명에게 묻는다 |

화면을 고친 PR과 시연 리허설 전에 쓴다. 빠른 시험 셋을 먼저 하고, 걸리는 데가 있으면 질문 목록으로 원인을 찾는다.

### 5.1 빠른 시험 셋

| 시험 | 방법 | 통과 기준 |
|---|---|---|
| 5초 시험 | 앱을 모르는 사람에게 랜딩과 대시보드를 각각 5초만 보여주고 가린다 | 랜딩: "영수증을 올리면 표와 보고서가 된다"를 말한다. 대시보드: "이번 달 얼마 썼는지"를 말한다 |
